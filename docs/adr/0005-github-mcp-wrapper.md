# ADR-0005 GitHub MCP 도구를 검색 범위를 고정한 래퍼로 감싼다

## 배경
GitHub MCP 서버(`langchain-mcp-adapters`로 연결)의 `search_code` 도구를 에이전트에게 그대로 주었더니 두 가지 문제가 있었다.
1. LLM이 검색어를 직접 만들면서 `Kafka user:apache`처럼 한정자를 덧붙인다. 그러면 `user:`가 두 개가 되어 OR로 검색되고, **남의 저장소 코드가 내 근거로** 잡힌다.
2. 이 프로젝트(gapmap) 저장소에는 기술 사전(`skills.yaml`)이 있어서 **모든 기술 이름이 검색된다** → 모든 기술이 "보유"가 된다.

## 결정
- MCP 도구를 그대로 노출하지 않고 `search_my_code` 래퍼를 만든다 (`api/app/agent/mcp.py`). LLM은 **기술 이름만** 넘긴다. LLM이 붙인 `user:`·`repo:`·`-repo:` 같은 한정자는 지우고, 검색 범위(`user:내아이디`, 제외할 저장소)는 코드가 붙인다.
  - `user:`와 `repo:`를 한 질의에 섞으면 파싱 오류가 나서 내 저장소와 팀 저장소를 따로 검색한 뒤 합친다.
- `GITHUB_EXCLUDE_REPOS`로 gapmap 저장소를 제외한다.
- 팀 프로젝트는 org 전체가 아니라 `GITHUB_TEAM_REPOS`에 지정한 저장소만 검색하고, 결과에 `[팀 프로젝트]` 라벨을 붙여 개인 코드와 구분한다.
- 검색 결과는 `저장소/파일: 코드 조각`으로 줄여서 컨텍스트를 아낀다.
- 토큰은 Fine-grained·Public 저장소 읽기 전용으로 쓴다. 토큰이 없으면 GitHub 도구만 빼고 동작한다.

## 결과
- 👍 코드 근거가 내 저장소에서만 나온다.
- 👍 작은 모델은 인자 하나(기술 이름)만 맞추면 된다. 검색 문법을 몰라도 된다.
- 👎 MCP의 다른 기능(이슈, PR 등)은 쓰지 않는다. 의존성 파일(`build.gradle`)을 읽어서 근거로 쓰는 것은 남은 과제다.
