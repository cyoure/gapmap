# ADR-0004 "부족"이 아니라 "근거 없음"

## 배경
이력서에 "Redis"라는 단어가 없다고 해서 Redis를 모른다고 단정할 수는 없다. 이력서에 안 썼을 수도 있고, 다른 표현으로 썼을 수도 있다. 반대로 RAG 유사도만으로 "보유"라고 판정하면, 의미가 비슷할 뿐인 문단이 근거로 둔갑한다.

## 결정
- 상태는 두 가지만 쓴다: **`보유`**(이력서에서 기술명이나 동의어를 찾음) / **`근거 없음`**.
- "보유" 판정은 **규칙**으로 한다: 기술명·동의어 정규식 매칭. 유사도로는 판정하지 않는다.
- "근거 없음"일 때는 RAG로 의미상 가장 가까운 이력서 문단을 **참고 힌트로만** 보여준다 (유사도 0.45 이상). 그 판단은 사용자가 한다.
- 사용자가 `PATCH /skills/{name}`으로 상태를 직접 고칠 수 있다 (웹 화면 통계의 상태 버튼). 직접 고친 값이 자동 판정보다 우선하고, `DELETE`로 되돌릴 수 있다.
  - 동의어로 고쳐도 표준 이름으로 저장된다 (`스프링부트` → `Spring Boot`).

## 결과
- 👍 판정의 근거(어느 파일, 어느 문장)가 표에 항상 같이 나와서 사용자가 검증할 수 있다.
- 👍 직접 고친 상태가 통계와 다음 리포트에 반영된다.
- 👎 이미 저장된 공고의 점수는 다시 계산하지 않는다 (알림의 "근거 없음 목록"은 반영됨). 점수를 다시 계산하는 기능은 남은 과제다.
