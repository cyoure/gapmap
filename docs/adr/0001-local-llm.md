# ADR-0001 LLM은 로컬 Ollama로만

## 배경
이력서에는 이름·연락처·학력·경력 같은 개인정보가 들어 있다. 클라우드 LLM API를 쓰면 분석할 때마다 이력서 조각이 외부 서버로 나간다.

## 결정
- 대화·추출 모델(`qwen2.5`)과 임베딩 모델(`bge-m3`)을 모두 **Ollama 컨테이너**에서 실행한다.
- 외부로 나가는 요청은 두 가지뿐이고, 이력서 내용은 보내지 않는다.
  - DuckDuckGo 검색: 에이전트가 만든 **검색어**(회사명 등)만, 100자로 자른다.
  - GitHub MCP: 내 **공개 저장소** 코드 검색 (읽기 전용 토큰).
- 모델명·URL은 `.env` → `config.py`로만 읽는다. 모델을 바꿀 때 코드를 고치지 않는다.
- 임베딩은 한국어 이력서·공고를 다뤄야 해서 다국어 모델 `bge-m3`를 쓴다.

## 결과
- 👍 네트워크 없이도 분석이 된다 (검색·GitHub 도구만 빠짐). 시연장 네트워크에 덜 의존한다.
- 👎 GPU가 없어서(AMD 내장 그래픽) CPU로 추론한다. 개발은 `qwen2.5:3b`를 쓰는데, 리포트가 다 나올 때까지 시간이 걸리고(그래서 스트리밍으로 먼저 보여준다) 품질에 한계가 있다(한국어 답변에 중국어가 섞임, 추출 누락). → 시연 전에 `7b`와 비교한다.
- 👎 작은 모델이 틀리는 것을 전제로 설계해야 했다 → [ADR-0002](0002-llm-output-validation.md), [ADR-0003](0003-calculation-in-functions.md).
