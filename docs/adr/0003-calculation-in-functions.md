# ADR-0003 점수·D-day·공부 순서는 순수 함수로 계산한다

## 배경
LLM에게 "매칭 점수를 계산해줘"라고 하면 같은 입력에도 매번 다른 숫자가 나오고, 날짜를 빼는 계산(D-day)도 자주 틀린다. 점수가 흔들리면 공고끼리 비교할 수도 없다.

## 결정
- `api/app/gap/score.py`의 순수 함수로 계산한다. 같은 입력이면 항상 같은 결과가 나온다.
  - `calc_match_score`: 필수 ×2, 우대 ×1 가중 평균 → 0~100점
  - `study_order`: 근거 없는 필수 기술 먼저, 그다음 우대 기술 (같은 그룹 안에서는 공고에 적힌 순서)
  - `calc_dday`: 마감일 − 오늘 (KST)
- 에이전트(Function Calling)에게도 **계산을 도구로** 준다. 이때 LLM이 넘기는 값을 그대로 믿지 않는다.
  - `calc_match_score` 도구는 LLM에게서 "새로 근거를 찾은 기술 이름(`newly_have`)"만 받는다.
  - 그 기술이 실제로 앞의 `search_resume` / `search_my_code` 결과에 나왔는지 도구가 LangGraph 상태(`InjectedState`)에서 직접 확인하고, 확인된 것만 반영한다.
- 리포트 화면에서도 표·점수·순서는 LLM 없이 함수 결과로 먼저 그리고, LLM은 그 뒤의 "공부 가이드" 문장만 쓴다.

## 결과
- 👍 점수를 재현할 수 있고, 저장된 공고끼리 비교할 수 있다. n8n 알림의 D-day도 같은 함수를 쓴다.
- 👍 작은 모델이 "근거 찾았어요"라고 거짓 주장을 해도 점수가 오르지 않는다.
- 👎 기술마다 정해진 가중치뿐이라, "Java 5년 이상" 같은 숙련도 차이는 반영하지 못한다.
