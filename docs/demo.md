# 시연 시나리오

> 기본은 **10분**(시연 6분 + 설명 4분). 발표 시간이 정해지면 아래 「시간별 조정」대로 늘리거나 줄인다.
> CPU 추론이라 LLM 응답이 느리다. **오래 걸리는 단계는 미리 실행해 두고, 현장에서는 결과를 보여주면서 한 단계만 라이브로 돌린다.**

## 한 줄 소개 (30초)

"채용공고를 붙여넣으면 내 이력서·GitHub 코드와 비교해서 **근거 없는 기술과 공부 순서**를 알려주는 로컬 AI 에이전트입니다.
이력서가 밖으로 나가지 않도록 LLM은 전부 로컬 Ollama에서 돌리고, 점수·날짜 계산은 LLM이 아니라 함수가 합니다."

## 흐름 (10분 기준)

| # | 시간 | 보여줄 것 | 화면·명령 | 수업 기술 |
|---|---|---|---|---|

| 2 | 2분 | 공고 붙여넣기 → **빠른 리포트**가 글자 단위로 흘러나옴 | 웹 `빠른 리포트` (공고 A) | FastAPI 스트리밍, 프롬프트 템플릿, Pydantic 스키마 검증 |
| 2+ | (+1분) | 복사 안 되는 이미지 공고 → 캡처 후 `Ctrl+V` → 글자 채워짐 → 확인·수정 | 공고 C 캡처 이미지 | 로컬 OCR(Tesseract, Docker 이미지에 설치) |
| 3 | 1분 | 보유/근거 없음 표 · 매칭 점수 · 공부 순서 | 리포트 결과 | RAG · ChromaDB(이력서 검색, 동의어 매칭), 계산은 함수 |

### 각 단계에서 할 말

1. **compose** — "컨테이너끼리는 localhost가 아니라 서비스 이름(`ollama`, `chroma`)으로 통신합니다. 모델·벡터·DB는 볼륨에 있어서 컨테이너를 지워도 남습니다."
2. **빠른 리포트** — "LLM이 공고에서 회사·필수·우대·마감을 뽑는데, 자유 텍스트가 아니라 JSON Schema로 출력을 제한하고 Pydantic으로 검증합니다. 실패하면 2번까지 재시도하고, **원문에 없는 기술은 버립니다.**"
2+. **이미지 공고** — "채용 사이트에는 이미지로만 된 공고가 많습니다. 캡처해서 붙여넣으면 이 PC 안에서 OCR로 글자를 뽑고, 바로 분석하지 않고 **사람이 오타를 확인한 뒤** 분석합니다. 기술명이 틀리면 갭 분석 전체가 틀어지니까요." (시간 부족하면 생략)
3. **결과 표** — "'부족'이 아니라 '근거 없음'입니다. 이력서에 안 썼을 뿐일 수 있으니까요. 점수는 필수 가중치가 더 큰 순수 함수라 같은 입력이면 항상 같은 점수가 나옵니다." (ADR-0003, 0004)
4. **에이전트** — "공고에 회사 설명이 없으니 에이전트가 스스로 `web_search`를 부르고, 근거 없는 기술은 `search_my_code`로 제 GitHub 코드에서 다시 찾습니다. D-day는 LLM이 세지 않고 `calc_dday` 함수가 계산합니다."
   - 🔧 줄이 안 나오면: 터미널에서 `docker compose logs -f api | grep "tool call"` 로 보여준다.
5. **후속 질문** — "같은 `thread_id`로 대화를 이어가서 방금 분석한 공고를 기억합니다."
8. **n8n** — "n8n은 DB를 직접 읽지 않고 api의 `/alerts/deadlines`를 호출합니다. D-day 계산과 문구를 한 곳(api)에서만 관리하려고요. 실제로는 매일 09시에 자동 실행됩니다." (ADR-0006)

## 시연용 공고

- **공고 A (빠른 리포트용)** — 실제로 지원하려는 회사 공고 하나. 필수/우대가 분명하고 이력서에 있는 기술(Spring, JPA)과 없는 기술이 섞인 것.
- **공고 B (에이전트용)** — 실제 회사 이름은 있지만 **회사 소개 문단을 지운** 공고. 그래야 에이전트가 웹 검색을 부를 이유가 생긴다.
- **공고 C (알림용, 직접 작성)** — 마감일을 **발표일 + 2일**로 맞춘 테스트 공고. 발표 전날 미리 `빠른 리포트`로 저장해 둔다.

```
[데모컴퍼니] 백엔드 개발자 (신입)
자격요건: Java, Spring Boot, JPA, MySQL
우대사항: Docker, AWS, Redis
마감: 2026-12-XX   ← 발표일 + 2일
```

> 공고 A·B는 사용자가 직접 붙여넣는다(크롤링 금지 원칙). 지난 테스트 공고 #1(11-26 마감)은 발표 때 이미 지나서 알림에 안 잡힌다.

## 발표 전 체크리스트

**전날**
- [ ] Docker Desktop 켜고 `docker compose up -d`, `curl http://localhost:8000/health`
- [ ] 공고 C 저장 → `curl "http://localhost:8000/alerts/deadlines?days=3"` 에 나오는지 확인
- [ ] 공고 A·B로 전체 흐름 리허설, **걸린 시간 기록** (CPU라 단계마다 편차 큼)
- [ ] 리허설 화면 녹화 → 현장에서 실패하면 녹화본으로 대체
- [ ] 통계가 의미 있도록 공고 3~5개 이상 쌓여 있는지 확인

**당일 (시작 10분 전)**
- [ ] 다른 무거운 프로그램 종료 (메모리 확보 — Ollama가 CPU·RAM을 많이 씀)
- [ ] 모델 미리 깨우기: `curl -N "http://localhost:8000/chat?q=안녕"` (첫 호출은 모델 로딩으로 느림)
- [ ] 탭 미리 열기: 웹 화면(8000), n8n(5679), Discord, 터미널(`docker compose logs -f api`)
- [ ] 공고 A·B·C 텍스트를 메모장에 준비

## 질문 대비

- **왜 로컬 LLM?** 이력서(개인정보)를 외부 API로 보내지 않으려고. 대신 CPU라 느림 → 트레이드오프. (ADR-0001)
- **LLM이 기술을 지어내면?** 스키마 검증 + 원문 대조로 원문에 없는 기술은 버림. (ADR-0002)
- **점수를 왜 LLM이 안 매기나?** 같은 입력에 매번 다른 점수가 나오면 비교가 안 됨. (ADR-0003)
- **한계는?** 3b 모델이 일부 기술("~운영 경험")을 놓치고, 답변에 중국어가 섞일 때가 있음. 알림의 점수는 분석 시점 값.
- **크롤링은?** 채용 사이트 약관 문제로 하지 않음. 공고는 직접 붙여넣음.
